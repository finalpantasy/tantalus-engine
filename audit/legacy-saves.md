# Legacy PC and Memoria save audit

Reference: local Memoria source snapshot `c716e1faaeee8c856cc10921234d017f1187b45b`. All findings below are source observations, not real-save runtime verification.

## Original PC base container

- `Assembly-CSharp/Global/Shared/Data/SharedDataBytesStorage.cs:565-668` reads metadata and one selected save block, decrypts it, and expects a decrypted payload of `DataSize + 4` beginning with `SAVE` or `NONE`.
- `SharedDataBytesStorage.cs:1285-1466` defines a 288-byte plaintext metadata structure, 320-byte metadata reservation, 10 slots, 15 saves per slot, 1,024-byte preview reservations, and 18,432-byte save blocks. `BaseSaveBlockOffset` is 153,920. The fixed PC container size derived from those constants is 2,937,152 bytes, including the autosave reservation.
- `Assembly-CSharp/Global/AESCryptography.cs:7-100` defines AES/Rijndael with a 256-bit key, 128-bit blocks, CBC mode, PBKDF2 (`Rfc2898DeriveBytes`) with 1,000 iterations, and a fixed password/salt. This is format compatibility information, not a security feature for protecting user data.
- `Assembly-CSharp/Global/JsonParser.cs:33-83` and the remaining parser map game state into a schema-driven typed tree. `JsonParser` is therefore not evidence of a plain-text JSON disk format.

Tantalus implements the AES layer and container framing in `crates/tantalus-legacy/src/saves/base.rs`: PBKDF2-HMAC-SHA1 (password is the two GUID strings concatenated, 8-byte salt `03 03 01 04 07 00 09 07`, 1,000 rounds) yields one 48-byte stream, the first 32 bytes are the AES-256 key and the next 16 the CBC IV; PKCS7 padding always adds 1-16 bytes (`SharedDataAesEncryption.GetCipherSize`). The key/IV and a sample ciphertext were cross-checked against Python `hashlib` and OpenSSL, not only against this crate. Metadata is the 39-byte header (`SAVE`, version f32, data size, latest slot/save, timestamp f64, finish flag, language, auto-login, achievement byte, rotation) inside a 288-byte plaintext, encrypted to 304 bytes at offset 0. A save block is read at `153,920 + 18,432 * (1 + slot * 15 + save)` (autosave: `153,920`), is `GetCipherSize(DataSize + 4)` bytes long, and must decrypt to exactly `DataSize + 4` bytes starting `SAVE` or `NONE`. Tantalus additionally refuses a negative `DataSize` or one whose cipher exceeds a block, where the reference would read into the next block.

`LegacySaveImporter::decode_base` returns the metadata and one decrypted block (`Saved` payload bytes or `Empty`). `BaseSavePayload` additionally implements the ordered primitive layer behind `ReadDataFromStream`/`WriteDataToStream` for an explicitly supplied field list: `System.Byte`, `System.SByte`, `System.Int16`, `System.UInt16`, `System.Int32`, `System.UInt32`, `System.Int64`, `System.UInt64`, `System.Single`, `System.Double`, `System.Boolean`, fixed 128-byte `System.String`, and fixed 4096-byte `String4K`. Fixed strings are strict UTF-8 and trim leading/trailing NUL bytes; payload decoding requires exact schema consumption and reports truncation with byte offsets. `BaseSaveSchemaNode` and `BaseSaveDataNode` implement the traversal shape behind `ParseJsonTreeToDataList`/`ParseDataListToJsonTree` for an explicit named tree: class fields are sorted by key, arrays preserve index order, duplicate/missing/unexpected keys and shape mismatches are explicit errors, and tree encoding/decoding round-trips through the primitive payload layer. This is still not the concrete `JsonParser` FF9 state schema. `BaseSavePreview` separately implements the pinned 965-byte `PREV`/`NONE` slot-preview record at `320 + 1024 * (slot * 15 + save)`: has-data, gil, play duration, win type, fixed location string, four optional serial/level/name character records, timestamp, and the 256-byte reserved tail. Decoding strict UTF-8 fixed strings, trims leading/trailing NUL bytes, validates the reserved tail, and maps `NONE` or `PREV` with `HasData == false` to `None`; unlike the reference coroutine, malformed ciphertext, magic, length, strings, or reserved bytes fail with offsets instead of returning a corrupted placeholder. `LegacySaveImporter::decode_slot` composes those verified layers into one read-only result for an explicit slot: metadata, `SAVE`/`NONE` block, non-autosave preview, and optional sidecar bytes. Autosaves correctly report no preview. Decoded base/slot/report structures and SimpleJSON trees are JSON-serializable with verified round trips for diagnostics and tooling. `LegacySaveImporter::inspect` remains the shallow path: bytes, SHA-256, expected fixed-size agreement, and `decoded: false`. `LegacySaveImporter::inspect_slot_file` is the on-disk read-only entry point: it loads the base container, derives the sidecar path with the reference's `GetMemoriaExtraSaveFilePath` naming (`memoria_sidecar_path`), reads the sidecar when present, reports filename pairing through the existing validator, and returns the full decoded slot with byte/hash observation. Missing base files and unreadable sidecars name their path in the error; a missing sidecar yields `sidecar_found == false` with pairing `NotChecked` and the base slot still decoded; corrupt sidecars fail with their byte location. No legacy source file is modified.

## Memoria extra data

- `SharedDataBytesStorage.cs:649-659` loads an optional sidecar through `JSONNode.LoadFromFile` and adds slot/save/file metadata only to the in-memory tree.
- `SharedDataBytesStorage.cs:671-735` removes `MemoriaExtraData` from the base tree before writing the base block, then writes the sidecar separately.
- `Assembly-CSharp/SimpleJSON/JSONNode.cs:511-518,557-597,614-631` shows recursive binary serialization using little-endian `BinaryWriter`/`BinaryReader` values. Tags are array 1, class 2, string 3, Int32 4, Double 5, Boolean 6, and Float 7; strings use the .NET seven-bit-length-prefixed UTF-8 representation.
- `SimpleJSON/JSONData.cs:55-88`, `JSONArray.cs:132-140`, and `JSONClass.cs:202-211` define value and collection encoding.
- `SharedDataBytesStorage.cs:1460-1466` derives `<base>_Memoria_<slot>_<save>.dat` or `<base>_Memoria_Autosave.dat`. The stored sidecar does not independently prove its base pairing. Tantalus therefore validates the expected filename against explicit slot/save coordinates and otherwise leaves pairing unchecked.

Tantalus rejects duplicate class keys, excessive nesting/nodes, invalid UTF-8, truncation, and unknown tags with byte locations rather than silently replacing required state. Trailing bytes are counted because the reference loader does not demand immediate EOF. The encoder/decoder tests use only project-owned synthetic data.

## Compatibility limits

No owned original or Memoria save has been supplied (none exists under the standard `LocalLow` location on this machine). Base AES, framing, the ordered primitive payload layer, and slot-preview framing are verified only against project-owned synthetic fixtures and independent known-answer values; real decryption, complete state-field mapping, sidecar/base behavior, and export are `NOT_RUN`. No legacy source file is modified by the inspector. Original save writing in the reference is a separate base/sidecar operation and is not used as a model for native atomicity.
