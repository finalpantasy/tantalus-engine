# Playable-game milestones

Goal: a playable game in Rust from new game to ending, using only data from the owned install and source-backed rules from the pinned Memoria checkout. This file turns the coverage ledger (`audit/game-coverage.md`) into ordered milestones per domain. It is a plan, not a compatibility claim. Real saves and real-game execution stay NOT_RUN.

Each milestone lists what it delivers, the source it follows, the data it reads, one check that proves it, and what exists today. Paths under Memoria are relative to `.reference/Memoria/Assembly-CSharp/`. IDs: B = battle, W = world, models and fields, A = audio, text, UI and tables, G = game flow and saves.

## Rules for every milestone

- Source first. A field Memoria does not define stays a named raw field and is listed as unknown.
- Memoria CSV and script files are cross-checks, never game data. Tables come from the install.
- Golden values come from running the reference code or reading the install, never from hand arithmetic.
- No milestone claims gameplay until its check runs against real data.

## A3/B3 notes (vanilla tables)

- Where the data lives: the installed managed assembly is the vanilla build. Its tables are C# static array initializers: straight-line IL in each type's static constructor (`newarr`, `newobj` of a data class, `stelem`, `stsfld`; primitive arrays via `InitializeArray` and a `FieldRVA` blob). There is no embedded manifest resource and no TextAsset for them. `Memoria/Data/*.csv` is Memoria's dump of the same values, used here only as the cross-check.
- Reader limits: `managed_il.rs` runs only constants, arrays, dictionaries, lists, constructor calls and static stores. Branches and calls with results stop it or become `Unsupported`; `battle_tables.rs` refuses any table that holds an `Unsupported` value. No game code runs.
- Whole-table comparison with Memoria CSVs (one-off script, not committed): level EXP/HP/MP 99 of 99, base stats 12 of 12, shops 32 of 32, synthesis 64 of 64, armor 136 of 136, equipment bonuses 176 of 176, items (price, shape, color, level, bonus, abilities) 256 of 256, item use 32 of 32, status sets 39 of 39, support-ability gem cost 64 of 64, learnable abilities 16 of 16 files match one of the 16 sets, weapons 85 of 88 (the other 3 pass a null model name, which Memoria writes as `<null>`).
- Differences that are Memoria's, not read errors: actions 5 and 6 (Life, Full-Life) differ in one camera flag and action 149 in script id (17 installed, 20 in the CSV); StatusData `ImmunityProvided` omits the status's own bit (all 32 rows match once that bit is removed).
- Command rows: for `kind` 1 the `ability` field is an index into the 192-entry command ability list (`BattleHUD.cs` reads `_FF9BMenu_ComAbil[ability + i]`); other kinds hold the ability id directly. 47 of 47 rows agree with Memoria's `Commands.csv` read that way.
- `AA_DATA` names: the installed constructor takes a name id but never stores it, so `name_arg` is kept as a raw argument only.
- Player tables (A3 remainder): method bodies run through `run_method`, which follows branches on integer constants only (loop counters, `switch`, int arguments) and records calls without running them; any other branch, tracked-object field access or opcode stops the run and the reader refuses a table that needed it. Names: `name`/`help` fields in the data tables are legacy offsets nothing reads; display names come from `EmbeddedAsset/Text/<resource>.mes` through the text bindings, indexed by row id (positions not yet checked against the install files). Default names are per language by menu type, mapped to characters through `menu_type_char_ids`.
- New game versus `crates/tantalus-game/src/new_game.rs` (read only): the install has 9 shared player slots (slots 5 to 8 start as Cinna, Marcus, Blank, Beatrix, via `GetCharID3`), while `new_game.rs` builds records for all 12 base-stat ids; it takes base stats and levels from Memoria CSVs rather than the install tables; gil 500, level 1 and 4 party slots agree with the install. Level 1 HP/MP from the install tables were not recomputed against it.
