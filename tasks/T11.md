## Outcome and scope

Implement deterministic package resolution, versioned module locks, provider conflict rules, a sandboxed WASM host, transactional host/module state, and externally built ARPG/card/loot fixtures. The first slice covers resolution and profile identity; executable WASM conformance remains separate evidence.

## Implementation approach

Resolve semantic-version requirements with deterministic backtracking. Dependencies precede dependents, with explicit load-order hints and stable package-ID tie breaking. Selected versions, feature dependencies, content hashes, and save schemas feed the shared `ProfileLock`. Additive content collisions and exclusive-provider conflicts fail before activation; declared replacements retain ordered override semantics.

## Verification and limitations

Verified on Windows x64 with Rust 1.96.0 using the current pre-commit source tree. Resolution is deterministic across available-package enumeration order and uses the shared native-save `ProfileLock`, not a parallel mod-only identity structure.

This proves package/profile foundation only. No executable module, WASM sandbox, external ARPG/card fixture, total conversion, or playable FFIX content is claimed. T10 base-save decoding and T05 visual capture remain open.
