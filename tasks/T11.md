## Outcome and scope

Implement deterministic package resolution, versioned module locks, provider conflict rules, a sandboxed WASM host, transactional host/module state, and externally built ARPG/card/loot fixtures. Resolver/profile identity and the executable ABI foundation are verified separately from complete system replacement.

## Implementation approach

Resolve semantic-version requirements with deterministic backtracking. Dependencies precede dependents, with explicit load-order hints and stable package-ID tie breaking. Selected versions, feature dependencies, content hashes, and save schemas feed the shared `ProfileLock`. Additive content collisions and exclusive-provider conflicts fail before activation; declared replacements retain ordered override semantics.

The experimental core-WASM ABI uses JSON buffers and explicit host imports. Each callback receives serialized module state and runs in a fresh guest instance. Host mutations, allocated IDs, events, and returned module state commit only after successful validation. Wasmtime fuel, memory, stack, input/output, and command limits are enforced. No precompiled native module cache or unapproved host imports are accepted.

## Verification and limitations

Verified on Windows x64 with Rust 1.96.0 using the current pre-commit source tree and Wasmtime 49.0.5. Actual WASM fixtures proved successful host commits, deterministic replay/fuel use, rollback after staged mutations and a guest trap, infinite-loop interruption, memory limits, malformed output rejection, ABI checks, and unavailable nondeterministic imports.

The ABI is experimental and is not yet WIT-generated. Fresh-instance state restoration favors correctness over callback performance; no performance claim is made. External ARPG/card/loot packages, provider wiring into the game, module migration callbacks, SDK bindings, and a trusted compiled-code cache policy remain open. T10 base-save decoding and T05 visual capture remain open.
