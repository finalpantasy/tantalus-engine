## Outcome and scope

Implement deterministic package resolution, versioned module locks, provider conflict rules, a sandboxed WASM host, transactional host/module state, and externally built ARPG/card/loot fixtures. Resolver/profile identity, executable ABI, and a narrow external action-mode fixture are verified separately from complete system replacement.

## Implementation approach

Resolve semantic-version requirements with deterministic backtracking. Dependencies precede dependents, with explicit load-order hints and stable package-ID tie breaking. Selected versions, feature dependencies, content hashes, and save schemas feed the shared `ProfileLock`. Additive content collisions and exclusive-provider conflicts fail before activation; declared replacements retain ordered override semantics.

The experimental core-WASM ABI uses length-delimited JSON buffers and explicit host imports. Each callback receives serialized module state and runs in a fresh guest instance. Host mutations, allocated IDs, events, and returned module state commit only after successful validation. Wasmtime fuel, memory, stack, input/output, and command limits are enforced. No precompiled native module cache or unapproved host imports are accepted.

The public Rust SDK and WIT declaration live under `sdk/`. The action-mode fixture is a separate Cargo project compiled for `wasm32-unknown-unknown`; its source, lockfile, binary, and SHA-256 are retained as project-owned conformance artifacts.

## Verification and limitations

Verified on Windows x64 with Rust 1.96.0 and Wasmtime 49.0.5. The action fixture was built with `cargo build --manifest-path tests/fixtures/synthetic/action_mode/Cargo.toml --release --target wasm32-unknown-unknown`. Rebuilding produced byte-identical WASM with SHA-256 `4a3e1e9d9e8583b664c9b5af416863bb5add508cc0d48ce1addb8ca3114cc107`.

The retained module drives six frames through the real host, deriving each frame's world input from previously committed host state. Assertions cover movement, target selection, damage/cooldown timing, enemy pursuit, one affixed loot instance allocation, no duplicate loot after victory, and HUD/attack/loot events.

The ABI and WIT declaration are experimental; WIT-generated bindings are not implemented. Fresh-instance state restoration favors correctness over callback performance; no performance claim is made. This small rules fixture is not an ARPG campaign, rendered gameplay, or complete provider integration. Card replacement, module migrations, package entry-point loading, and a trusted compiled-code cache policy remain open. T10 base-save decoding and T05 visual capture remain open.
