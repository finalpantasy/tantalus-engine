## Outcome and scope

Implement deterministic package resolution, versioned module locks, provider conflict rules, a sandboxed WASM host, transactional host/module state, and externally built ARPG/card/loot fixtures. Resolver/profile identity, executable ABI, and narrow external action/card fixtures are verified separately from complete game/provider integration.

## Implementation approach

Resolve semantic-version requirements with deterministic backtracking. Dependencies precede dependents, with explicit load-order hints and stable package-ID tie breaking. Selected versions, feature dependencies, content hashes, and save schemas feed the shared `ProfileLock`. Additive content collisions and exclusive-provider conflicts fail before activation; declared replacements retain ordered override semantics.

The experimental core-WASM ABI uses length-delimited JSON buffers and explicit host imports. Each callback receives serialized module state and runs in a fresh guest instance. Host mutations, allocated IDs, events, and returned module state commit only after successful validation. Wasmtime fuel, memory, stack, input/output, and command limits are enforced. No precompiled native module cache or unapproved host imports are accepted.

The public Rust SDK and WIT declaration live under `sdk/`. Action and card fixtures are separate Cargo projects compiled for `wasm32-unknown-unknown`; source, lockfiles, binaries, and SHA-256 values are retained as project-owned conformance artifacts.

## Verification and limitations

Verified on Windows x64 with Rust 1.96.0 and Wasmtime 49.0.5. Fixtures were built with `cargo build --manifest-path <fixture>/Cargo.toml --release --target wasm32-unknown-unknown`.

Action-mode SHA-256: `4a3e1e9d9e8583b664c9b5af416863bb5add508cc0d48ce1addb8ca3114cc107`; a rebuild was byte-identical. It drives six frames using previously committed host state and verifies movement, target selection, damage/cooldown timing, pursuit, one affixed loot allocation, no duplicate loot, and HUD/attack/loot events.

Card-mode SHA-256: `5813524aeb8e1eae90d526546c284a27efb7c632a6b246ea1cf24927f42aac81`. An exclusive resolved provider runs a two-round match with deterministic AI card choice, scores, completion, one reward allocation, progression/UI events, and no reward duplication on repeated completion. Two hosts replay identically.

Four package-entrypoint tests additionally stage a module-only package, resolve its exact content hash, instantiate its named entrypoint, and execute a real callback. They reject traversal, malformed WASM, duplicate/unsupported entry points, tampered bytes, and stale profile hashes; changing module bytes changes package identity.

Migration-fixture SHA-256: `ed01c16dd6805cb589bad701c815c935b98eef879b59b75495c34b409995a925`. Two tests prove a pure schema 1-to-2 migration with preserved existing state and history, and unchanged source data after a trap. Migration currently binds one explicit section per call.

These are synthetic rules fixtures, not an ARPG campaign, Tetra Master compatibility, rendered gameplay, or full provider lifecycle. The ABI/WIT declaration is experimental; WIT-generated bindings are not implemented. Multi-module migration orchestration, a trusted compiled-code cache policy, and useful-work performance tests remain open. T10 base-save decoding and T05 visual capture remain open.
