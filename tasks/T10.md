## Outcome and scope

Implement native save envelopes with stable world/entity/item/encounter identity, profile and module state, recoverable immutable generations, validated atomic publication, migration boundaries, unknown-section retention, and exactly-once outcome markers. Legacy codecs are a separate source-audited adapter; no real original/Memoria save verification is claimed without an owned installation.

## Implementation approach

Use deterministic JSON for the initial versioned envelope and content digests. Each commit stages and syncs a new generation before atomically replacing the current pointer. A generation links to its predecessor for recovery. Load plans explicitly report missing required modules and required migrations; normal continuation refuses unsafe states. Outcome records and their effects share one snapshot transaction.

## Verification and limitations

Verified on Windows x64 with Rust 1.96.0 using the current pre-commit source tree. Native commits use immutable digest-protected generations, synced staging files, atomic current-pointer replacement, predecessor recovery links, and explicit load/migration plans. Outcome tests prove the synthetic snapshot/marker contract at each injected failure boundary; individual game adapters must still construct effect-plus-marker snapshots correctly.

The Memoria sidecar codec follows pinned source at `c716e1faaeee8c856cc10921234d017f1187b45b` and uses only project-owned fixtures. The base container's AES-256-CBC/PBKDF2 layer, metadata, and `SAVE`/`NONE` block framing are implemented and verified only on project-owned synthetic containers plus an independent Python/OpenSSL known-answer check. `BaseSavePayload` now ports the ordered primitive and fixed-string payload layer for an explicitly supplied schema, including all source numeric widths, `System.String`/`String4K`, NUL trimming, exact-consumption validation, and typed round trips. `BaseSavePreview` ports the separate 965-byte `PREV`/`NONE` slot-preview record, including offsets, encrypted container access, four character entries, fixed strings, reserved-tail validation, and empty/dataless handling. `BaseSaveSchemaNode`/`BaseSaveDataNode` add the source-compatible named tree traversal: class fields are visited in sorted-key order, arrays in index order, shape mismatches fail with context, and encoded trees round-trip through the primitive payload layer. `LegacySaveImporter::decode_slot` combines the already verified base metadata/block, non-autosave preview, and optional Memoria sidecar into one read-only inspection result; it is not a native save import. The decoded base/slot/report structures and SimpleJSON trees are serializable for diagnostics and tooling. Constructing the concrete FF9 state schema and mapping values into every named game field remain separate work. No owned original/Memoria save was available; real compatibility, export, and recovery verification is NOT_RUN. This task does not make the vertical slice playable and does not resolve the T05 visual failure.
